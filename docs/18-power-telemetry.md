# Энергопотребление: Проверка 2026-10-11

## Результат

На работающем Proxmox (Lenovo 10T8S0K300, Intel i7-8700T,
ядро 7.0.14-4-pve) доступны счётчики Intel RAPL. Проверка только читала
sysfs и cgroup; пакеты не устанавливались, настройки питания и гости не менялись.

В 15:26 UTC сняты шесть последовательных интервалов по 5 секунд:

| Зона RAPL | Диапазон средней мощности за интервал | Среднее за 30 секунд |
| --- | --- | --- |
| package-0, процессорный пакет | 17.992-24.578 Вт | 20.064 Вт |
| core, ядра внутри package-0 | 17.147-23.731 Вт | 19.219 Вт |
| uncore | 0 Вт | Счётчик не менялся; не считать доказательством отсутствия потребления |
| dram, показания зоны памяти | 1.416-1.588 Вт | 1.471 Вт |

Это короткий снимок обычной работы, не среднесуточная статистика и не нагрузочный
тест. RAPL является аппаратно предоставляемой телеметрией/оценкой энергии,
а не заменой поверенного внешнего измерителя. Независимой проверки точности
зоны dram на этом оборудовании не проводилось.

`core` входит в `package-0`: складывать их нельзя. `package-0 + dram`
в этом замере составляет около 21.5 Вт по показаниям этих зон, но **не является
мощностью всего сервера**.

## Чего Нет

В RAPL не обнаружена зона всей платформы (psys). В `/sys/class/power_supply`
нет устройств, `/dev/ipmi*` отсутствуют. hwmon содержит acpitz, nvme, coretemp
и iwlwifi_1, но не предоставляет файлов мощности/энергии. `turbostat`,
`sensors` и `ipmitool` не установлены; чтение RAPL возможно без них.

По доступным интерфейсам нельзя достоверно получить сумму потребления платы,
SSD, вентиляторов, сетевых устройств и потерь блока питания. Нельзя выдавать
RAPL CPU за весь сервер или добавлять произвольные фиксированные ватты.

## VM И LXC

Подтверждены читаемые накопительные `cpu.stat/usage_usec`:

- VM: `/sys/fs/cgroup/qemu.slice/<VMID>.scope/cpu.stat`.
- LXC: `/sys/fs/cgroup/lxc/<CTID>/cpu.stat` (агрегат группы и потомков).

За отдельный 10-секундный интервал VM 101 использовала 6.91 CPU-секунды
(69.1% одного ядра). Другие VM: 102 - 4.28%, 103 - 1.01% одного ядра;
контейнеры 100/104/105/106/107/108 - 0.01-0.69% каждый.
Это не проценты всего 12-поточного процессора и не ватты.

Следовательно, есть данные для модели относительного вклада гостей в CPU-энергию.
Но отдельного энергетического счётчика каждого гостя нет. Простое распределение
RAPL по CPU-времени не учитывает частоту, вид инструкций, простои, общий cache,
I/O, работу ядра хоста и аппаратное транскодирование Jellyfin. Память нельзя
точно распределять по выделенным/занятым гигабайтам. Нельзя распределять всю
мощность только между гостями, забывая хост и базовое потребление.

## Возможный Мониторинг

1. Читать RAPL на хосте каждые 5-10 секунд, без отдельного агента в гостях.
2. Рассчитывать среднюю мощность: `delta_energy_uj / 1000000 / delta_seconds`,
   используя монотонное время, учитывая переполнение `max_energy_range_uj`
   и сбрасывая базовую точку после перезагрузки/смены счётчика.
3. Сохранять CPU package и dram отдельно; не суммировать вложенные зоны.
4. Одновременно собирать CPU-время VM/LXC и хоста. Расчётные доли подписывать
   как оценку CPU-энергии, а не полное потребление гостя.
5. В интерфейсе явно показывать «CPU, RAPL», «Память, RAPL» и
   «Оценка CPU по гостям». Для всего сервера выводить «Нет датчика».
