# Аудит Системы 2026-10-11

## Область И Вывод

Проверены работающие Proxmox, CT 100/104/105/106/107/108, VM 101/103,
веб-интерфейс Domain Router, инвентаризация, root-агенты, авторизация,
Vaultwarden и резервирование. Home Assistant проверен по HTTP, без доступа к его
учётным записям. Это эксплуатационный аудит и выборочное ревью кода, не полный
пентест, не проверка всех пакетов на CVE и не подтверждение всех паролей в vault.

Архитектура подходит для одного домашнего сервера: публичные сайты идут через
Cloudflare Tunnel, приватные сервисы через отдельный Tailscale gateway,
хранилище паролей изолировано от UI. Новый слой SSO или собственный криптосервис
сейчас не нужен. Основные недостатки относятся к аварийному восстановлению,
MFA, обновлениям и понятности состояния доступа, а не к маршрутизации.

Прямой Tailscale-доступ Proxmox не зависит от CT 100/107, но все компоненты
по-прежнему зависят от одного физического хоста, питания и uplink. Watchdog NIC
не заменяет UPS, запасной канал, резервный сервер или внешние backup.
Фактические ACL/grants всей tailnet и MFA у внешних аккаунтов Cloudflare/Tailscale
не подтверждены этим аудитом. Приватный адрес сам по себе не означает «только владелец».

## Ресурсы

Хост: Intel i7-8700T, 6 физических ядер / 12 потоков, 31 960 MiB видимой ОЗУ.
На момент замера load average 1.21 / 1.06 / 0.93, MemAvailable 8 126 MiB,
swap занят примерно на 5 MiB. За последние два дня в доступном журнале ядра
не найдено OOM, I/O error или нового e1000e Hardware Unit Hang.

SSD-пул local-lvm: 348.8 GiB, физически занято около 20%, metadata 1.13%.
SMART обоих SSD имеет PASSED; NVMe: 44 C, 11% износа, 0 media errors,
124 unsafe shutdowns за всю историю устройства. Это не гарантия отсутствия будущего отказа.
Корень Proxmox занят на 14%. CT имеют 15–22% занятости своих rootfs.
VM 101: около 21 GiB занято, 124 GiB свободно; VM 103: 3.3 GiB занято,
27 GiB свободно. Высокий cache Linux не равен нехватке RAM.

Суммарные лимиты RAM гостей близки к ёмкости хоста, поэтому новые VM нельзя
планировать только по текущим 8 GiB available: при одновременной нагрузке запас
уменьшится. CPU oversubscription допустим при текущем малом load, но не означает
22 физических ядра. Лимиты существующих гостей в этом аудите не менялись.

## Улучшения Интерфейса

- В «Доступах» по умолчанию только сохранённые учётные записи, без DNS и служебных портов.
- Фильтры: «Учётные записи», «SSH-сервисы», «Без привязки», «Все сервисы».
  SSH-фильтр относится к обнаруженным сервисам, не угадывает протокол ручных записей.
- Мгновенный поиск без перезагрузки и передачи каждого поискового запроса в URL.
  GET-форма сохранена как fallback без JavaScript.
- Число найденных записей и пустое состояние; группы автоматически раскрываются при поиске.
- Копирование готовой SSH-команды для обнаруженных SSH-сервисов с логином.
  Аргументы shell-экранируются; пароль никогда не входит в команду.
  У ручной записи протокол не объявлен, поэтому SSH не угадывается по названию.
- Состояния «Порт не отвечает», «Нет свежих данных», «Tailscale-доступ выключен».
  Существование привязки к vault не выдаётся за проверку пароля или права подключения.
- Проверка/смена пароля UI вынесена из event loop в рабочие потоки с лимитом
  две операции Argon2 одновременно, чтобы не блокировать страницу и ограничить RAM.

При аудите в UI было **12** привязок, а в Vaultwarden **13** записей.
Это разные независимые списки: удаление привязки не удаляет секрет в vault.
Отсутствующие старые привязки автоматически не восстанавливались.

## Backup Управляющей Части

На Proxmox требуется пакет `age` из Debian и **публичный** recipient.
Можно использовать тот же recipient, что для Vaultwarden; приватная identity
остаётся на доверенном устройстве, никогда не передаётся Proxmox.

```bash
apt-get install age
bash scripts/install-control-plane-backups.sh /путь/backup-recipient.txt
systemctl status control-plane-backup.timer
systemctl start control-plane-backup.service
journalctl -u control-plane-backup.service -n 20 --no-pager
```

Расписание: ежедневно 04:45 по времени хоста + случайные 0–10 минут,
`Persistent=true`. Копии: `/var/lib/vz/dump/control-plane/control-plane-*.tar.age`,
root-only, retention 30 дней после успешной новой копии. oneshot-служба после
успешного выполнения имеет состояние `inactive (dead)`; смотрите exit status и journal.

Состав: согласованный SQLite online backup CT 100; routes.yml; Caddy;
Cloudflare-конфигурация и credentials; настройки root integration agent;
UI systemd drop-ins (allowed zones, vault, inventory); forced-command SSH identity;
CT 107 firewall/network; host network/guest-configs/inventory decisions/authorized key.
Из снимка БД удалены только браузерные сессии, не из работающей базы.
При восстановлении потребуется обычный вход заново.

Во время сбора используются существующие locks маршрутов и интеграций;
при незавершённой замене Tunnel backup откажет, а не сохранит промежуточное состояние.
Временные файлы находятся в root-only `/run` (tmpfs), удаляются по завершении.
Незашифрованный архив на постоянный диск не записывается. Рабочие сервисы не
останавливаются; блокируется только одновременное изменение конфигурации.

Не входят: диски VM/LXC, медиа, прикладные данные, root-пароли/хэши ОС,
Tailscale node identities, приватные host SSH keys и данные Vaultwarden.
Для vault действует отдельная копия из [инструкции хранилища](16-access-vault.md).
Для приложений нужны отдельные проверенные Proxmox/прикладные backup.

## Перенос И Проверка

На доверенном компьютере, в защищённом каталоге:

```bash
scp root@PROXMOX_IP:/var/lib/vz/dump/control-plane/'control-plane-*.tar.age' /защищённый/каталог/
python3 scripts/verify-control-plane-backup.py /путь/control-plane-ВРЕМЯ.tar.age \
  --identity /путь/age-identity.txt --age /путь/age
```

Проверяются полная расшифровка age-stream, допустимые пути, отсутствие ссылок и
дубликатов, обязательные файлы, SQLite integrity/foreign keys. Секреты и хэши
не печатаются, текущий сервер не изменяется. Первая проверенная копия содержала
84 archive members, 12 access links и одного администратора.
Vault backup также проверен: один аккаунт, 13 зашифрованных записей, SQLite OK.
Это не полноценный тест развёртывания и расшифровки записей владельцем.

Для реального восстановления сначала развернуть базовую систему из
[инструкции с нуля](08-rebuild-from-zero.md). Расшифровать копию на доверенном
устройстве в отдельный защищённый каталог и проверить её до переноса.
Не распаковывать архив поверх `/` и не заменять сетевые файлы нового хоста
автоматически. Восстанавливать согласованные конфигурации по компонентам.
UI остановить на время замены app.db, удалить старые WAL/SHM и вернуть владельца
`domain-router-ui:domain-router-ui` и права `0600`. Caddy и nftables сначала
проверить через `caddy validate` / `nft --check`. Tailscale узлы регистрировать
заново; не клонировать живые node identities. Проверить forced-command key и host pinning.

После восстановления сравнить маршруты, решения включённости сервисов и запустить
`verify-tailscale-services.sh`, затем проверить входы владельцем.
Отдельный тест Vaultwarden проводить в изоляции: восстановить data, открыть vault
мастер-паролем и проверить чтение нескольких записей/вложений. Он пока не выполнен.

## Проверка И Ограничения

Автотесты покрывают auth/CSRF, маршруты, CAS-привязки, экранирование, inventory,
root agents, безопасные SSH-команды, backup paths/retention и expiry parsing.
Финальный прогон: 99 passed; отдельно проверены Bash/JavaScript syntax,
локальные ссылки документации и шаблоны секретов, включая достижимую Git-историю.
UI проверяется на desktop и mobile, включая фильтры и отсутствие горизонтального
переполнения. Рабочие пароли, публичные маршруты, ACL и root SSH policy не менялись.
Регистрация Vaultwarden и приглашения закрыты, webadmin выключен, Rocket на loopback;
Funnel для CT 100/107/108 выключен. Мониторинг backup-failure с уведомлениями
и автоматический off-host перенос пока не настроены.

Первоисточники: [Vaultwarden backup](https://github.com/dani-garcia/vaultwarden/wiki/Backing-up-your-vault),
[Tailscale key expiry](https://tailscale.com/docs/features/access-control/key-expiry).
Истечение ключа останавливает связь; изменение expiry для серверов остаётся
отдельным решением владельца, а не скрытым действием аудита.
